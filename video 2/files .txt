1. whoami — Who am I?
whoami

Shows the currently logged-in user.
Example:
parrot

Useful when you're working with multiple users or administrative privileges.
Remember
whoami → Who am I logged in as?

2. Revisiting Navigation
ls
ls

Lists the contents of the current directory.
cd
cd directory

Changes the current directory.
Example:
cd Desktop

pwd
pwd

Prints the current working directory.
Example:
/home/parrot/Desktop

cd ..
cd ..

Moves one directory up.
cd /
cd /

Takes you directly to the root of the filesystem.
3. clear
clear

Clears the visible terminal screen.
Alternative:
Ctrl + L

Important
clear doesn't delete anything.
It doesn't:
- Delete files
- Change directories
- Reset the filesystem
- Remove command history
It only cleans the screen.
4. The Root Directory /
The Linux filesystem starts at:
/

This is called the root of the filesystem.
When you run:
cd /
ls

you'll see directories such as:
bin
boot
dev
etc
home
lib
mnt
opt
root
run
sbin
srv
tmp
usr
var

These directories have different purposes.
5. 🔥 The Big Linux Concept
"Everything is a file"
This was the biggest concept introduced in the video.
Linux represents many things as files:
Commands             → files
Configuration        → files
Network settings     → files
Hard drives          → files
Printers             → files
CD/DVD devices       → files
Other devices        → files

This is one of the fundamental ideas behind understanding Linux.
6. /bin — Binary Commands
bin stands for binaries.
cd /bin
ls

This directory traditionally contains essential command binaries.
Examples include commands such as:
ls
cp
rm
cat

And here's the interesting part:
ls itself is a file.
When you type:
ls

you're executing a program whose binary is stored somewhere on the filesystem.
7. cat — Display a File
cat filename

cat comes from concatenate.
It outputs the contents of a file to the terminal.
Example:
cat ls

When used on a binary executable such as ls, you'll see what looks like complete garbage / binary data.
That's normal.
You're looking at the raw contents of the executable rather than running it.
Important distinction
ls       → executes the ls program
cat ls   → displays the contents of the ls file

8. cp — Copy
cp source destination

Copies a file.
Example:
cp ls networkchuck

This creates a copy of ls called:
networkchuck

The copy contains the same binary contents.
Therefore, running:
networkchuck

can behave like the original ls program.
Basic structure
cp WHAT_TO_COPY WHERE_TO_COPY

9. sudo — Temporary Administrative Privileges
Sometimes Linux doesn't allow a normal user to modify certain files.
Example:
cp ls networkchuck

may produce:
Permission denied

You can use:
sudo cp ls networkchuck

sudo allows you to execute a command with root/administrator privileges for that command.
Think:
normal command
      ↓
permission denied
      ↓
sudo command
      ↓
administrative privileges

Important
sudo doesn't permanently make you root.
It gives the command elevated privileges.
And be careful with sudo, especially with commands such as rm.
10. rm — Remove
rm filename

Removes a file.
Example:
rm networkchuck

If you don't have permission:
sudo rm networkchuck

⚠️ Be careful
rm doesn't normally send files to a recycle bin.
So:
sudo rm /usr/bin/ls

would attempt to remove the actual ls executable.
Never experiment with rm on important system files.
11. /sbin — System Administration Binaries
The video describes /sbin as "super bin."
cd /sbin
ls

It contains commands associated with system administration.
One example:
adduser

12. adduser
Used to create a user.
Example:
sudo adduser superbin

Linux then asks for information such as:
- Password
- Full name
- Other optional information
This demonstrates that /sbin contains tools used for system administration.
13. /usr
Another major directory is:
/usr

Inside it you'll find directories such as:
/usr/bin
/usr/sbin
/usr/local
/usr/lib

The video demonstrates that:
/bin
/sbin

and:
/usr/bin
/usr/sbin

contain a lot of overlapping commands.
14. /usr/bin
Contains many command binaries.
For example:
/usr/bin/ls

The important question becomes:
When I type ls, which copy of ls is actually being executed?

That's where which comes in.
15. which — Find Where a Command Lives
which ls

Example output:
/usr/bin/ls

This tells you which executable will be found when you type:
ls

You can also use:
which cat
which cp
which rm

And even:
which networkchuck

if you created a command with that name.
Remember
which command
      ↓
Where is the executable for this command?

16. /usr/local
The video introduces:
/usr/local

as a place where commands/programs you create or install locally can be stored.
This is an important directory to recognize.
17. /usr/lib
Contains shared libraries used by programs.
Think of libraries as code/resources that multiple programs can use instead of every program having to contain everything itself.
18. /boot
/boot

Contains files needed for the system to boot/start Linux.
19. /var
/var

Contains things such as:
- Log files
- Data that changes while the system runs
- Web-application-related files
You'll encounter /var frequently in Linux administration and cybersecurity.
20. /tmp
/tmp

Used for temporary files.
The video describes these as files that can disappear after a reboot or similar system events.
21. /home
This is where normal users have their personal directories.
Example:
/home/parrot

If you create another user:
/home/superbin

may exist for that user.
Think:
/home
├── parrot
└── another-user

Each normal user gets their own home directory.
22. /root
Don't confuse:
/

with:
/root

/
The root of the entire filesystem.
/root
The home directory of the root/administrator user.
The root user doesn't normally live inside:
/home

Instead:
/root

is their home directory.
You may need:
sudo ls /root

to view it.
23. /dev — Devices
This is one of the most important directories for Linux and cybersecurity.
/dev

stands for devices.
Linux represents hardware and virtual hardware as files under /dev.
Examples can include:
Hard drives
Partitions
Terminals
USB devices
Virtual devices

In your Parrot VM, you saw things like:
/dev/sda
/dev/sda1

or depending on the virtual disk configuration:
/dev/vda
/dev/vda1

24. Virtual Disks
The video demonstrates:
vda
vda1

as virtual disks.
On other Linux systems you may see:
sda
sda1

Concept
/dev/sda
     ↓
entire disk

/dev/sda1
     ↓
partition on that disk

For your VirtualBox Parrot installation, you previously saw:
VBOX HARDDISK — 50 GiB
/dev/sda

So /dev is literally where Linux exposes your VM's virtual hardware.
25. Why cat on a Disk Is Crazy 😂
Because Linux treats devices as files, you can technically try to read the device file.
For example:
sudo cat /dev/vda

or:
sudo cat /dev/sda

This produces a huge amount of binary-looking garbage.
You can stop a running command with:
Ctrl + C

⚠️ Don't casually experiment with writing to device files.
Reading a device is one thing; writing to the wrong device can destroy data.
26. /etc — Configuration
Another extremely important directory:
/etc

Contains system and application configuration files.
The video specifically looks at networking configuration.
For example:
/etc/network/

and:
/etc/network/interfaces

The interfaces file can contain network-interface configuration, including IP-address-related configuration on systems that use this traditional networking setup.
The video demonstrates:
sudo cat /etc/network/interfaces

to view it.
Important
Not every modern Linux system configures networking through this exact file anymore, so don't assume every distro will look identical.
27. /mnt — Manually Mounted Drives
/mnt

is traditionally used for manually mounted filesystems/drives.
For example, you might manually mount a disk there.
Conceptually:
/mnt
 ↓
things you manually mount

28. /media — Automatically Mounted Media
/media

is commonly used for removable media that the system automatically mounts.
For example:
USB drive

Concept:
/media → automatically mounted removable media
/mnt   → manually mounted filesystems

🧠 Linux Filesystem Cheat Sheet
Directory	Purpose
/	Root of the filesystem
/bin	Essential command binaries
/sbin	System administration binaries
/usr	User programs, libraries, etc.
/usr/bin	Many executable programs
/usr/sbin	System administration programs
/usr/local	Locally installed/created programs
/usr/lib	Shared libraries
/boot	Boot-related files
/dev	Device files
/etc	Configuration files
/home	Normal users' home directories
/root	Root user's home directory
/var	Logs and changing application/system data
/tmp	Temporary files
/mnt	Manually mounted filesystems
/media	Common location for automatically mounted removable media
